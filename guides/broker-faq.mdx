Answers to common questions about the WhiteBIT Broker Program.

## Eligibility and approval

### Broker Program eligibility

The Broker Program is open to partners that operate trading for end customers, and enrollment is approval-gated — every application is individually reviewed before provisioning is enabled. Apply by emailing `institutional@whitebit.com`; see [Eligibility and approval](/guides/sub-account-integration#eligibility-and-approval).

### KYC reliance for brokers

KYC reliance — WhiteBIT relying on the partner's own customer verification — may be available to eligible licensed partners under a written agreement, assessed case by case and never enabled by default. The eligibility criteria are on the [Broker Guide](/guides/sub-account-integration#eligibility-and-approval).

### End-customer KYC branding

The end-customer KYC verification flow is WhiteBIT-branded and cannot be white-labeled. See [Eligibility and approval](/guides/sub-account-integration#eligibility-and-approval).

## Program terms

### Revenue share

The revenue share is up to 40% of the trading fees generated by referred customers; the applicable rate and any additional commercial terms are agreed individually at enrollment. The canonical terms are on the [Broker Program page](https://institutional.whitebit.com/broker-program); see also [Program terms](/guides/sub-account-integration#program-terms).

### Revenue reporting

Earnings are reported through the WhiteBIT Analytical Dashboard; the program does not expose a dedicated fee-share endpoint. Programmatic reconciliation combines the sub-account list with per-sub-account trade history — see [Revenue monitoring](/guides/sub-account-integration#revenue-monitoring).

## Integration models

### Sub-account and Fast API Key models

The Broker area covers two architectures: partner-operated sub-accounts and customers' own accounts via Fast API Key. The [Broker Overview](/guides/broker-overview) compares the two architectures, and [Partner Solutions](/guides/partner-solutions#choose-an-integration-path) maps the routing.

### Sub-account API key limits

Each sub-account supports up to 50 API keys, independent from the main account and from other sub-accounts, each with its own IP whitelist and permission scope. See [Account architecture](/guides/sub-account-integration#account-architecture).

## Copy trading

### Copy-trading availability

Copy trading is a partner use case built on the Fast API Key flow. Access is approval-gated — not available by default and subject to an internal review; attribution and commercial terms are confirmed with WhiteBIT at enrollment. See the [Copy Trading guide](/guides/copy-trading).

### Order execution in copy trading

The partner places orders with each follower's OAuth-issued key, and execution happens inside the follower's own account; the account acted on is determined by which key signs the request. See [Copy Trading architecture](/guides/copy-trading#architecture).
