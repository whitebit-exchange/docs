Shared questions about the WhiteBIT Wallets & White-label program — Wallet-as-a-Service (WaaS) and Crypto-as-a-Service (CaaS).

## Choosing an offering

### WaaS versus CaaS

WaaS is the wallet and settlement building block for adding wallets and payouts to an existing product; CaaS is the full white-label exchange delivered as a dedicated branded instance. CaaS uses the WaaS wallet building block for end-customer wallets. See the [overview](/guides/platforms-overview#choose-waas-or-caas).

## Integration models

### Available models

Both offerings use managed sub-accounts (Model A), attribution (Model B), or a gated KYC-reliance variant of Model A. See [integration models](/concepts/integration-models).

### Pooled account

A single pooled (omnibus) account for all end users is not offered, because pooled custody conflicts with client-fund segregation and Travel Rule requirements. Each model keeps segregated sub-accounts with a master account acting only as a settlement hub. See [why not a pooled account](/concepts/integration-models#why-not-a-pooled-account).

## Onboarding and access

### Onboarding phases

Institutional onboarding has two phases: Phase 1 grants crypto operations after KYB, and optional Phase 2 adds EUR/SEPA fiat access. See [Institutional Onboarding](/institutional/onboarding).

### Crypto deposit enablement

Crypto deposits are disabled by default on institutional accounts and cannot be enabled through the API. Request enablement through the account manager or `institutional@whitebit.com`. See [crypto deposit enablement](/guides/caas-faq#crypto-deposit-enablement).

## Testing

### Test environment availability

WhiteBIT does not offer a public testnet or sandbox. Test on the live API with minimum order sizes and low-minimum assets; Demo Tokens are available for risk-free spot practice. See the [Go-Live Checklist](/best-practices/go-live-checklist).

## Compliance

### MiCA and Travel Rule for EEA end users

For EEA users, MiCA restricts some stablecoin operations, and the Travel Rule governs EEA and Turkey transfers; both affect the assets and flows available to those end users. See [Regulatory Compliance](/institutional/compliance) and [Travel Rule](/concepts/travel-rule).
