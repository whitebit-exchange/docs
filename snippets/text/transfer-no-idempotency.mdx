The transfer request takes no idempotency key, and two identical requests move the funds twice. After a timeout or a
`5xx` response, the transfer can still complete, so check the transfer history for a record that matches the request
and was created after the failed request was sent. Resend the transfer only when no such record exists.

The caller cannot attach its own reference to a transfer, so the match is ambiguous when two identical transfers are sent close
together. An integration that transfers per purchase stores its own record of each transfer before the call, and
treats no match or an ambiguous match as a manual check, not an automatic resend.
