Place a spot market order that matches immediately against the order book at the available prices. A market order never rests, so the response is already terminal — `FILLED` when the book absorbed the whole order, `PARTIALLY_FILLED` when it ran out first.

## Place market order

### Request parameters

<WsSchemaTable fields={orderMarketPlaceParams} />

The unit of `amount` depends on the side, which is the one trap in this method. A sell sizes in [stock](/glossary#stock) — the base asset. A buy sizes in [money](/glossary#money) — the quote asset to spend. For stock sizing on both sides use [`order_market_stock_place`](/websocket/order-management/order-market-stock-place).

The `post_only`, `ioc`, and `rpi` flags carry no meaning for a market order and are ignored.

<WsMessageExample data={exOrderMarketPlaceRequest} />

### Response

<WsMessageExample data={exOrderMarketPlaceResponse} />

The `result` object is the standard order object — see the [order object reference](/websocket/order-management/overview#order-object). A spot market order reports `type` `2` and `price` `"0"`, because it carries no limit price. Read the achieved cost from `deal_money` and the matched size from `deal_stock`.

<Warning>A thin order book does not produce an error. When the book runs out before `amount` is exhausted, the status comes back `PARTIALLY_FILLED` with the unspent balance in `left`, and the order is not retained. Check `left` rather than assuming a full fill; an order book with no liquidity at all returns error `12`.</Warning>

## Update frequency

This method is client-initiated: the server answers each `order_market_place` request with a single response frame carrying the same `id`.
