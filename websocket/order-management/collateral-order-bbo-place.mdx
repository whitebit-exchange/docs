Place a margin or futures limit order priced from the current best bid or offer. The role semantics match the spot [`order_bbo_place`](/websocket/order-management/order-bbo-place) method, and the same ordinary limit order comes back.

## Place margin BBO order

### Request parameters

<WsSchemaTable fields={collateralOrderBboPlaceParams} />

The `bbo_role` parameter decides which side of the spread supplies the price.

| Role | Price source | Effect |
|------|-------------|--------|
| `1` maker | Own-side best — the best bid for a buy | Adds liquidity; `post_only` is set implicitly |
| `2` taker | Opposite-side best — the best ask for a buy | Crosses the spread and matches immediately |

<WsMessageExample data={exCollateralOrderBboPlaceRequest} />

### Response

<WsMessageExample data={exCollateralOrderBboPlaceResponse} />

The response is an ordinary margin limit order reporting `type` `7` — no BBO marker survives placement. The `price` field records where the order landed. See the [order object reference](/websocket/order-management/overview#order-object).

<Warning>No re-pegging happens. The price is resolved once, at placement, and the order then behaves like any other resting limit order as the order book moves away from it.</Warning>

## Update frequency

This method is client-initiated: the server answers each `collateral_order_bbo_place` request with a single response frame carrying the same `id`.
